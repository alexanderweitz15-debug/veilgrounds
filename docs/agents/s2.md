# S2: replay browser (FEATURE-GAP 6.6) + post-game error list (6.3)

Branch `feat/s2-replay-2` (continues `feat/s2-replay`, merged with main 5fc933b).

## Built

- Recording: `Recorder.observe(sim)` (sim worker, read-only) collects markers (kill / tower / inhib / nexus / epic) and the player's pattern events; `Replay` carries `markers`, `player`, `winner`, slim `botLog` (only `error` + `attention` nodes). `Game.exit()` fetches the replay from the worker for a decided game (3 s cap) -> `SessionResult.replay`.
- Storage: `src/replay/store.ts`, IndexedDB via `kv.ts`, one blob per replay + index, cap 12 (oldest dropped), injectable backend.
- Seek engine: `src/replay/cloneSim.ts` (freeze / thaw of the sim), `engine.ts` (checkpoint every 600 ticks, background index pass, seek = nearest checkpoint + re-sim). Worker `src/replay/worker.ts`, link `replayLink.ts`, protocol `protocol.ts`.
- Viewer: normal Game view fed by the replay link (`GameOpts`), bar `src/ui/replayBar.ts`: play/pause, speed 0.5/1/2/4/8x, timeline with kill / structure / epic markers (own kills/deaths ringed), click/drag seek, arrow keys +-10 s, view of any of the 10 players, camera follow / free. After a seek the client state is rebuilt (`resetForSeek`, kill/tower tally from markers, epic respawn clocks).
- Browser: `src/ui/replayBrowser.ts` (main menu nav "Replays": watch / delete).
- Error list: `src/stats/errorList.ts` (bots: injectedError + detection time + "my bad"; attention windows per bot; player: `Replay.player` from `src/stats/playerPatterns.ts`, same shape/vocabulary), view `src/ui/errorListView.ts`, rendered in the post-game screen; every row "Replay moment" opens the viewer 5 s before.
- de/en: keys `rp.*`, `pe.*` (test checks every error id / pattern id / attention cause has a sentence).

## Measured (important)

`tools/scratch/s2seekTime.ts`, 30-min bot game, machine under heavy load (25 agents): late-game sim step ~10-13 ms.
- Seek cost = thaw + at most 600 steps: measured 122 steps 1.7 s, 244 steps 2.7 s, 361 steps 3.9 s, 483 steps 4.7 s. On an idle machine this is expected to be ~3-5x less (early-game step 0.6 ms in the tests), i.e. under ~2 s; NOT verified idle. If it is too slow on the lead's machine: lower `CHECKPOINT_EVERY` (src/replay/engine.ts) to 300 (memory for ~180 checkpoints not measured).
- Index pass: 100 ticks/s under that load (542 s for 30 min). Idle machine expected 5-10x faster (not verified).
- Design decision: a seek that is past the index waits in the worker until the background pass reaches it (bar shows "Preparing timeline x %"), instead of blocking for the whole gap. So a cold far seek in a long game is limited by the index speed, not 2 s. Seeks inside the indexed range are one checkpoint interval at most.
- 30-min replay JSON: 2.1 MB (markers 46, slim bot log 667 KB); cap 12 replays ~ 26 MB.
