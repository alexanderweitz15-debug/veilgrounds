# S3 load time, round 3 (branch perf/s3-load-3)

Goal: start < 5 s warm, cold no worse than the runtime bake. Result: both met; CI now ships baked strips by default.

## What changed
1. **WebP strips** (`src/render/bakeEntry.ts`, `tools/bakeSprites.mjs`): lossy WebP q0.92 (env `BAKE_FORMAT=png` for lossless, `BAKE_QUALITY`).
   52 files 64.4 MB (PNG) -> 20.5 MB (WebP, ground included). Visual diff (`tools/scratch/s3webpdiff.mjs`, composite over grey,
   51 strips): mean PSNR 41.8 dB, worst strip 39.0 dB (siege0), worst channel error 73 on single edge pixels, mean error 0.57 / 255.
   The 8x amplified difference image shows only faint noise on the sprite outlines; invisible at 1x.
   **CI default flipped** (`vite.config.ts`): `CI` set -> bake on; local builds stay opt-in `BAKE_SPRITES=1`; `BAKE_SPRITES=0` turns it off.
   Validated with `CI=true vite build`: bake 74 s, 20.5 MB. A failed / browser-less bake still never fails the build.
2. **Atlas starts at once** (`src/main.ts` `start()`): `getChampionAtlas` is requested in parallel with the game chunk and the renderer
   setup, no longer after `new World()`. `sheets.ts` now keeps a progress listener list so the loading banner still works for the second caller.
3. **Ground as ImageBitmap** (`terrain.ts`): the stored / shipped ground is decoded pre-flipped (`imageOrientation: 'flipY'`) and handed to the GPU
   directly instead of being copied through a 4096² canvas (64 MB + a main-thread `drawImage`). Orientation checked against a painted ground
   (screenshots identical).
4. **Progressive loading** (`game.ts`, `sheets.ts` `getStandInAtlas`, `atlas.ts` option `still`): if the full champion atlas is not ready after
   2.5 s (no shipped strips, nothing in IndexedDB: dev server, fork build, failed bake), a stand-in atlas (one still pose per animation and
   direction, 64 px cells) starts the match; the full atlas replaces it when ready (`setChampionAtlas` is re-callable). Warm / shipped starts finish
   before 2.5 s and never bake it.
5. **First frame**: `html, body` background was near-black `#121110` until the menu script ran; now the main-menu map tone (`style.css`).

## Measurements (built game, vite build + static server, headless Edge, `?play=classic`, ms until champions applied, 3 runs)
Machine was quiet for these (earlier runs under 100 % CPU load from other agents were 3-10x slower and are discarded).

| case | before (main 70602b6, no strips) | after (CI build, WebP strips) |
|---|---|---|
| cold, unthrottled | 14437 / 14465 / 14741 | 2365 / 2281 / 2302 |
| cold, 50 Mbit / 20 ms | not measured (runtime bake does not use the net) | 3502 / 3585 / 3363 |
| warm, first game visit before (IndexedDB filled by the game itself) | 23616 / 18615 / 18471 (strips are PNG-encoded after the match started, not stored yet) | 1480 / 1997 / 1396 |
| warm, after 80 s in the menu (precache done) | 2372 / 1964 / 1309 | same as above (nothing to precache: shipped strips are stored when fetched) |
| cold without strips (dev / fork), `nobake` build, loaded machine | 19.5 / 17.9 / 21.3 s (full atlas) | 10.9 / 10.0 / 11.6 s (stand-in starts the match, full atlas follows) |

Findings:
- The old "warm 6-15 s" number came from the strips of the first visit not being stored yet (the PNG encode runs after the match started). With
  shipped strips the first visit already stores them, so warm = 1.4-2.0 s from the first return visit on.
- A 10-champion match needs ~6 MB of strips (not all 20 MB): 50 Mbit costs ~1.2 s over unthrottled.
- Stand-in: first version (64 px cells, all frames) only moved the start from ~20 s to ~14 s because the frame count, not the cell size,
  dominates the bake cost; one still frame per animation gives ~3 s of bake time. Start still waits for the full bake competing for CPU (~10 s).
- WebP decode is ~0.3 s slower per strip than PNG (probe from round 2); not visible in the table above, so no PNG transcode was added.
